## Why

Passing isolated checks does not prove the complete local application works or that the 3D view is usable. Delivery must establish reproducible startup, observed integration/visual evidence and a candid account of the empirical model validation still required.

## What Changes

- Provide documented Windows installation, local startup and shutdown, plus an offline runtime after dependency installation and asset build.
- Verify import-to-run-to-comparison-to-export/reopen and 3D replay through actual application workflows.
- Produce a technical guide, Spanish user guide and acceptance report with observed results and limitations.
- Define a future field-validation protocol, preserving unknown measurements and the preliminary status of current observations.
- Dependencies: 01 through 05 implemented and accepted.
- Non-goals: claiming empirical validity from automated tests, collecting new observations automatically, deployment, installer executable and unsupported performance guarantees.

## Capabilities

### New Capabilities

- `validation-and-delivery`: reproducible local operation and evidence-based release acceptance.

### Modified Capabilities

None.

## Impact

Future launcher, installation instructions, manuals, end-to-end checks and acceptance report. This change adds observable delivery behavior without introducing a new simulation algorithm. All implementation and verification tasks remain pending until authorized and actually performed.
